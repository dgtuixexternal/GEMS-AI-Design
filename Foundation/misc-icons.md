
# GEMS Design System — Foundation / Misc Icons

> **MANDATORY:** All specialized UI icons MUST use official GEMS Figma Misc Icon Components. Use Misc Icons only when required by functionality, component specifications, or product context.

## 1. Sources & Priority

**Source of Truth**
- [GEMS Misc Icons](https://www.figma.com/design/vaAJgd6yZ7l9TrIuF04671/GEMS-Design-System?node-id=294-6991)
- GEMS Components, Page Samples & UX Pattern Samples within the same Figma Design System.
- GEMS Foundation `icons.md` for general icon usage.

**Priority Order**
1. **Component First:** Preserve icons already defined within official GEMS Components.
2. **Misc Icons:** Use specialized GEMS Misc Icon Components for their intended functions.
3. **General Icons:** Use official GEMS Line/Outline Icons for standard UI actions and navigation.
4. **Page Samples & UX Patterns:** Read relevant examples for actual icon selection, size, placement, and visual consistency.

Read only references relevant to the current task. Do not scan unrelated pages or components.

Official GEMS Component specifications always take priority.

## 2. Context-Based Misc Icon Selection

AI MUST determine whether a General Icon or specialized Misc Icon is appropriate based on functionality and product context.

| Misc Icon | When to Use |
|---|---|
| Featured Icon | Prominent visual indicators required by official components or layouts |
| Featured Icon Outline | Outlined featured indicators when specified by GEMS |
| File Type Icon | Actual file formats and attachments |
| Folder Icon | Folders and directory structures |
| Check Icon | Completion and checklist indicators |
| Check Item Text | Checklist items with supporting text |
| Star Icon | Actual rating or star values |
| Dot | Supporting indicators and approved status contexts |
| Emoji | Only when required by GEMS patterns or approved content |
| Social Icon | Supported social platforms or authentication providers |
| Country Icons | Country or region identification |
| Payment Method Icon | Actual supported payment methods |
| Integration Icons | Supported external platforms and integrations |
| Illustration Result | Corresponding success or error outcomes |
| Feature Text | Supported feature-description layouts |

**Selection Rules**
- Identify the element's purpose before choosing an icon.
- Follow icon usage already established in GEMS Components.
- Use specialized Misc Icons only when their function is required.
- Use General Line/Outline Icons for regular actions, navigation, and standard UI indicators.
- Read relevant Page Samples and UX Patterns to understand contextual usage.
- Do not introduce specialized icons solely for decoration.
- Do not imply unsupported product features, integrations, payments, or statuses.

## 4. Component Integration & Visual Consistency

Misc Icons MUST follow their parent GEMS Component specifications.

**Rules**
- Preserve existing icon instances within official GEMS Components.
- Follow original icon placement, size, alignment, and spacing.
- Use existing icon variants rather than manually changing visual properties.
- Maintain consistent icon usage across related pages and components.
- Use official GEMS Color, Typography, Spacing, Radius, and Effect Styles.
- Standard UI actions MUST prioritize General Line/Outline Icons.
- Filled, branded, or specialized styles are permitted when defined by the official Misc Icon component.
- Do not mix icon styles arbitrarily.
- Do not add Featured Icons or result illustrations automatically to every Card, Section, or Empty State.
- Maintain accessibility through appropriate text labels or accessible names when needed.

## 5. Human Approval & Missing Icons

If no suitable official GEMS Misc Icon exists:

1. Check relevant GEMS Misc Icon categories and component examples.
2. Check whether a suitable General GEMS Icon is available.
3. Ask the user to approve an existing alternative or provide an official custom asset.
4. Apply the selected option only after explicit approval.

**Rules**
- Do not automatically import external icon libraries.
- Do not invent, generate, or manually redraw specialized icons.
- Do not substitute unrelated icons.
- Do not interpret silence as approval.
- If the icon is optional, omit it instead of introducing an unapproved replacement.

## 6. Strict Misc Icon Rules

**MUST**
- Use official GEMS Misc Icon Components.
- Prioritize icons defined within parent GEMS Components.
- Select icons based on function and product context.
- Follow official sizes, colors, variants, and states.
- Preserve original component references and visual properties.
- Read relevant Page Samples and UX Patterns for contextual usage.
- Maintain consistent icon mapping and accessibility.
- Obtain Human Approval for unsupported alternatives.

**MUST NOT**
- Create custom Misc Icons when official GEMS components exist.
- Replace specialized components with manually styled General Icons.
- Invent icon sizes, colors, shapes, states, or variants.
- Modify official component properties.
- Add specialized icons solely for decoration.
- Introduce unsupported social platforms, integrations, or payment methods.
- Represent false status, rating, completion, or verification information.
- Use emoji as substitutes for standard UI icons.
- Import external icon libraries without authorization.
- Detach official icon components unnecessarily.

**Fallback:** If no appropriate official Misc Icon is available, request Human Approval for an alternative or custom asset. If the icon is optional, omit it.

**Core Principle:** Use Misc Icons only for their specialized functions. Standard UI actions use GEMS General Line/Outline Icons. Official component specifications always take priority.
